# Установка Closure в постоянную папку Chrome

Скрипт `scripts/install_chrome.py` распаковывает готовый ZIP или копирует собранный `dist/` в постоянную папку. Репозиторий и загруженный ZIP после подключения этой копии в Chrome можно убрать. **Папку, которую напечатает установщик, нужно оставить:** Chrome загружает расширение из неё.

Требуется Chrome 119+. Для скрипта нужен Python 3.10 или новее. Для сборки из исходников дополнительно нужны Node.js 22+ и npm. Скрипт использует только стандартную библиотеку Python, без pip-пакетов и без сетевых запросов.

## Вариант 1: из исходников одной командой

В корне репозитория:

```sh
npm ci
npm run install:chrome
```

Команда собирает расширение и устанавливает файлы в постоянную папку. Скрипт печатает точный путь, например на macOS:

```text
/Users/your-name/Library/Application Support/Google/Chrome/Unpacked Extensions/Closure
```

Для уже существующей установки из папки `Quiet Archive` скрипт сохраняет это старое имя папки. Название расширения в Chrome остаётся **Closure**. Старое имя каталога нужно для сохранения загруженного пути и идентификатора, а значит — настроек и архива.

Проверить, куда будут установлены файлы, без записи в каталог Chrome:

```sh
npm run install:chrome -- --dry-run
```

При этом сборка `dist/` создаётся заново, но файлы Chrome не меняются.

## Вариант 2: готовый ZIP без npm

Скачайте **оба файла** из [релиза](https://github.com/zagum/quiet-archive/releases/latest):

- `closure-chrome.zip` — готовая сборка;
- `install_chrome.py` — самостоятельный установщик.

Положите их рядом. В терминале перейдите в эту папку и выполните:

```sh
python3 install_chrome.py --zip closure-chrome.zip
```

Распаковывать ZIP вручную не требуется. Путь с пробелами заключайте в кавычки:

```sh
python3 install_chrome.py --zip "/path/with spaces/closure-chrome.zip"
```

Если ZIP лежит рядом с самим скриптом и называется `closure-chrome.zip`, можно выполнить просто:

```sh
python3 install_chrome.py
```

В Windows при необходимости используйте `py` вместо `python3`. Если Python не установлен, установите его с [python.org](https://www.python.org/downloads/) либо используйте обычную ручную распаковку и Load unpacked из README.

## Первый раз: подключить папку в Chrome

После успешного завершения скрипта:

1. Откройте `chrome://extensions` в нужном профиле Chrome.
2. Включите **Режим разработчика / Developer mode**.
3. Нажмите **Загрузить распакованное расширение / Load unpacked**.
4. Выберите **точную папку из вывода скрипта**, внутри которой лежит `manifest.json`.
5. Откройте значок **Closure** на панели и проверьте настройки.

Скрипт устанавливает файлы. Первое подключение подтверждается в интерфейсе Chrome. Скрипт не меняет `Preferences`, `Secure Preferences`, политики, служебные каталоги `Extensions` или регистрацию расширений. Сервер и аккаунт для работы Closure не нужны.

Каждый профиль Chrome подключается отдельно и хранит свои настройки с архивом. Одна и та же постоянная папка с кодом может использоваться несколькими профилями.

## Обновления без потери настроек

Запустите ту же команду повторно, затем нажмите **Перезагрузить / Reload** на карточке установленного Closure в `chrome://extensions`. Закройте открытый popup перед обновлением и дождитесь сообщения об успешной установке файлов перед Reload.

**Не удаляйте расширение из Chrome для обычного обновления. Не подключайте его заново из другой папки.** У распакованных расширений путь может влиять на идентификатор; новый идентификатор означает отдельное локальное хранилище.

Если прежняя версия загружена из `dist/`, Downloads или другого нестандартного каталога, укажите именно этот путь:

```sh
python3 scripts/install_chrome.py --source dist --target "/exact/path/already/loaded/in/chrome"
```

Скрипт сам распознаёт только свои стандартные папки `Unpacked Extensions/Closure` и `Unpacked Extensions/Quiet Archive`. Он не читает настройки Chrome, чтобы искать другие установки. Перенос в новый путь с миграцией данных — отдельная операция: сначала экспортируйте архив из старого расширения, не удаляя его; этот установщик такой перенос хранилища не выполняет.

## Где находятся файлы

| Система | Каталог по умолчанию                                                      |
| ------- | ------------------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/Google/Chrome/Unpacked Extensions/Closure` |
| Linux   | `${XDG_CONFIG_HOME:-~/.config}/google-chrome/Unpacked Extensions/Closure` |
| Windows | `%LOCALAPPDATA%\Google\Chrome\User Data\Unpacked Extensions\Closure`      |

Для другого каталога данных Chrome, например другого канала браузера или нестандартного профиля запуска:

```sh
python3 scripts/install_chrome.py --source dist --chrome-data-dir "/path/to/chrome-user-data"
```

Здесь нужен **корень user-data**, а не вложенная папка `Default` или `Profile 1`.

Если существуют обе стандартные папки — `Closure` и `Quiet Archive` — скрипт попросит явно выбрать `--target`. Он не угадывает, какая копия сейчас загружена.

## Проверка и резервная копия

Перед установкой скрипт проверяет ZIP, Manifest V3, имя Closure/Quiet Archive, service worker, popup и ссылки на ресурсы из manifest. Отвергает выход путей за пределы каталога, символические ссылки, дублирующиеся пути, специальные файлы, зашифрованные архивы и пакеты больше 64 MiB или 5000 записей. Чужую существующую папку не перезаписывает.

При обновлении старая сборка сохраняется рядом, например:

```text
Closure.backup-20261024T120000Z-a1b2c3d4
```

Это копия **кода**, не резервная копия пользовательского архива. Настройки и архив остаются в хранилище профиля Chrome; резервную копию данных делайте кнопкой **Export backup** на странице архива.

Новая сборка сначала полностью готовится в соседней временной папке. Затем каталоги заменяются; при ошибке замены установщик пытается вернуть старую папку. Если система помешает и откату, в сообщении будет указан путь сохранившейся резервной копии.

Для ручного возврата к старому коду отключите Closure в Chrome, переместите текущую папку кода в сторону, верните нужную резервную копию **на прежний точный путь**, затем включите и перезагрузите расширение. Не меняйте служебные файлы профиля Chrome. При обычном обновлении резервная копия автоматически не удаляется.

После установки/перезагрузки уже открытые страницы без защитного скрипта могут пропускаться до их обычной перезагрузки. Установщик сам страницы не перезагружает и вкладки не закрывает.
